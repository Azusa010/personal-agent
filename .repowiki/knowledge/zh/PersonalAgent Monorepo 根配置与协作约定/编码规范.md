- 跨语言协议字段变更必须同时更新 Zod schema、Pydantic 镜像模型与对应 fixture JSON，缺一不可。
- Pydantic 模型统一使用 `ConfigDict(extra="allow")`，禁止 `extra="ignore"` 静默丢弃未知字段。
- 可选字段采用 Zod `optional`（收 undefined 不收 null），Python 侧以 `None` 默认值配合 `model_dump(exclude_none=True)` 对齐线上形状。
- 安全校验函数入参一律使用 `string` 类型，调用点传入的值视为不可信，路径解析先在 binder 做字符串运算再经 `resolveWithinRootReal` 做 realpath 二次校验。
- Monorepo 内依赖方向严格单向：`apps/desktop` 与 `services/agent-runtime` 不得互相 import，跨进程通信仅通过 stdio NDJSON JSON-RPC。
- 状态枚举以 TS `readonly const` 数组定义并由 `typeof ...[number]` 派生类型，SQL CHECK 约束只拦截非法值，状态转换规则放在 Repository 层。
- 协作采用陪练模式：AI 完整写出协议 schema/fixtures、类型接口、migration DDL、仓储 SQL 样板、接线与全部测试（作为验收标准）；核心业务逻辑本体（状态机转换表、执行体副作用编排、判定/校验函数、算法段）以 `// TODO(你填): ...`（Python 侧 `# TODO(你填): ...`）标记留给项目主人手写，全仓搜索该标记即为待办清单，填完必须删除标记。
- 每个 TODO(你填) 必须自带足够上下文：输入输出契约、不变量与边界条件、失败时的稳定错误码、对应验收测试文件名；AI 不得代填，主人填完前相关测试允许红，填完后 `pnpm verify` 必须全绿。
- 验收流程：主人填 TODO → AI 跑 `pnpm verify` → 对照指导书该 TASK 的 Validation 列核对 → 通过后标 ✅ 并提交；归属拿不准时按「这段代码错了会不会造成副作用/安全问题/契约漂移」判断，会则留给主人。先例是 `tool-execution-repository.ts` 的 `ALLOWED_TRANSITIONS` 转换表（主人已填写，逐格一致性断言测试由 AI 预先写好）。
