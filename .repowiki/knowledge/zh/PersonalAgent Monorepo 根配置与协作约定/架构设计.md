本模块为整个 PersonalAgent monorepo 的根级配置与契约层，不承载业务代码，仅通过 `package.json`、`pnpm-workspace.yaml`、`.editorconfig`、`.gitattributes`、`.gitignore` 和 `AGENTS.md` 统一多语言工程边界：
- 工作区划分：`pnpm-workspace.yaml` 将 `apps/*`（Electron 桌面端）、`packages/*`（共享 Zod 协议包）、`services/*`（Python agent-runtime）纳入同一 workspace，并启用 `nodeLinker: hoisted`。
- 脚本编排：根 `package.json` 的 `scripts` 作为统一入口，通过 `pnpm --dir` 转发到各子包执行 dev/typecheck/lint/test/build，并通过 `uv run --project services/agent-runtime` 调用 Python 工具链。
- 依赖方向约束：`apps/desktop` → `packages/protocol`（Zod schema + tsconfig paths alias `@personal-agent/protocol`），`services/agent-runtime` 通过 Pydantic 镜像与 fixture JSON 对齐协议，三者之间禁止反向或跨进程直接 import，TS 与 Python 间仅走 stdio NDJSON JSON-RPC。
- 协议双模型同步：Zod schema（`packages/protocol/schemas/*.ts`）、Pydantic 模型（`services/.../models.py`，`extra="allow"`）、共享 fixture（`packages/protocol/fixtures/*.json`）构成单一事实来源的三步同步机制。
- 安全策略链：工具调用必须经 Scope → Retriever → Binder → Executor → Path-Guard 五层校验，路径解析在 binder 中做字符串运算并在 executor 前经 realpath 二次校验。
- 状态机与 DB CHECK 分离：合法值集合由 SQL CHECK 约束保证，转换规则由 Repository 层实现，TS 侧用 `readonly const` 数组派生类型，测试需遍历状态数组验证真库一致性。
- 门禁命令：`pnpm verify` 串联 typecheck、lint:ts、lint:py、test（pack/ts/py），`verify:all` 追加 build。
