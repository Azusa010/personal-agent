### 切片
- 定义：将 Phase/Task 拆分为可独立验证的最小交付单元（如 Slice 1、Slice 2），每个切片包含明确的目标、修改位置、验收方式，完成后即推进下一个切片。这是本项目推进开发的基本节奏单位。
- 别名：slice

### 指导书
- 定义：项目架构与任务规划文档 `architecture-personal-agent-v0.1.md`，定义 4 个 Phase、29 个 Task、GOAL-001~004 及各项约束（SEC/GUD/REQ/DEP/FILE）。所有开发决策需对照此文档，偏离需记录 ADR。
- 别名：architecture-personal-agent-v0.1.md

### 冒烟
- 定义：Phase 0 的验证方式转变：从纯单测转向手动运行 `pnpm dev`，通过肉眼观察链路行为（如点 Send IPC 看状态）来验证端到端连通性。用于 Electron 主进程生命周期 + React UI 等难以单测的场景。
- 别名：冒烟测试、manual smoke test

### 四门禁
- 定义：每次提交前必须同时通过的四个检查：TS 行为（vitest）、TS 类型（typecheck:node + typecheck:web）、Python 行为（pytest）、Python lint（ruff check）。强调"绿≠对"，四类门禁缺一不可。
- 别名：门禁、四道门禁

### 单一事实来源
- 定义：跨边界数据（如 PdfEntry、协议常量）只在一个地方定义（protocol 包），其他模块通过 import/type 派生使用，禁止手写副本。用于消灭契约漂移和重复定义。
- 别名：SFS、单一真相源

### wire 码
- 定义：跨进程/跨语言传输的错误码或协议字段值（如 ERROR_CODE 中的 PROTOCOL_INVALID_REQUEST、FILESYSTEM_ROOT_UNAVAILABLE），必须放在 packages/protocol 中作为 wire 层契约，Main 内部错误码则放 desktop error-codes.ts。
- 别名：wire code、协议码

### 白名单桥
- 定义：Electron Preload 层通过 contextBridge 暴露给 Renderer 的固定 API 集合（window.personalAgent），每个方法对应一个写死的 channel 名，绝不暴露 ipcRenderer 本身。是 SEC-002 的核心实现。
- 别名：preload 桥、contextBridge 白名单

### trusted tool
- 定义：Python 侧放在 `src/personal_agent/tools/` 下的纯领域逻辑函数（如 resolve_root、list_pdfs），不含协议/JSON-RPC 知识，由 runtime.py 的 handler 调用。与 protocol/handler 层严格分离。
- 别名：可信工具、tools 层

### 完成闸口（DeliverableVerifier）
- 定义：任务从 running 翻到 completed 的唯一判定入口（main/verification/verify-deliverables.ts）。表驱动八项检查：摘要结构、页码落地（判 facts 里的引用落在重读真实 PDF 的页集合内）、计划步骤跑完、时间线完整、批准对上执行（argsHash 交叉比对）、拒绝后无副作用、文件落在目标、Reminder 带幂等键。必需性按计划推导：计划里有 extract_pdf / filesystem.move / scheduler.create 才要求对应交付物。fail-closed：取证有缺口一律拒绝，校验器异常按未通过处理。
