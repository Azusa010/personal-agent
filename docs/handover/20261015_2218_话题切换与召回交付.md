### 2.1 各模块核心职责与契约明细

#### Step 2：主从日志隔离的可克隆子 Agent 池
- **物理隔离**：子代理全流程轨迹严格写入 `./logs/subagent_traces/{run_id}.jsonl`，与主账本物理解耦；
- **因果重放**：`TraceIsolator.read_trace()` 按正序因果流（`1 -> 2 -> 3...`）完整回放；
- **浓缩回灌**：子代理结束后通过 `SubagentBackfeed.prepare_backfeed_payload` 生成浓缩结论，主账本仅追加一条 `subagent_completed` 事件（携带 `subagent_run_id` 物理路径引用）。

#### Step 3：高水位滑动窗口与时间门卫
- **70% 警戒水位滚褶**：`SlidingWindowLedger.compact_if_needed()` 动态比对活跃 Token 预算，触发旧事件折叠更新 `rolling_task_summary`；
- **成对工具保护铁律**：`find_safe_compaction_boundary` 逆向对齐用户轮次，绝不切断 `tool_call` 与 `tool_result`；
- **时间门卫与 Bridge Buffer**：`TimeGatekeeper.check_and_handle_timeout()` 检测空闲超时，封存旧现场至 `epochs/epoch_{id}_summary.md`，自增 `epoch_id`，保留最近 2 轮作为桥接缓冲区，并将摘要重置为系统引导语；
- **纪元现场召回**：`recall_epoch(epoch_filename)` 支持按文件名读取指定纪元 Markdown 归档。

#### Step 4：180度转弯话题切换与三层漏斗召回
- **秒级水印瞬移（Quantum Leap）**：`TopicSwitchHandler.archive_current_topic_and_switch()` 封存旧任务为 `epoch_{id}_summary.md`，自增纪元，并将 `window_watermark` 跃迁至新话题前夕（`switch_user_seq_id - 1` 或自适应倒序最新 `user` 事件），旧任务万级 Token 彻底脱离活跃窗口；
- **三层漏斗并联召回**：
  - **Tier 1**（常驻轻量）：`ThreeTierRetriever.get_system_index()` 安全读取 `memory/INDEX.md`；
  - **Tier 2**（显式定向）：`ThreeTierRetriever.read_memory_topic(topic_name)` 读取 `memory/topics/*.md`，文件不存在时提供包含可用列表的明确异常；
  - **Tier 3**（深层翻账）：`ThreeTierRetriever.search_raw_events(query, limit)` 委托主账本底层倒序精准检索。

#### 既有并发工具执行器与读写分流架构（`loop.concurrency`）
- **核心模块**：[`services/agent-runtime/src/personal_agent/conversation/loop/concurrency.py`](file:///d:/BaiduNetdiskDownload/dailyProjects/Projects/PersonalAgent/personal-agent/services/agent-runtime/src/personal_agent/conversation/loop/concurrency.py)
- **底层架构与调度契约**：
  1. **动态读写属性判定（`is_read_capability`）**：
     - 基于 `CapabilityDescriptor.kind`（`READ` / `WRITE`）动态判定，支持显式传入 `is_read_fn`；
     - 严守 **Fail-Closed 原则**：未注册或未知的能力一律视为 `WRITE` 串行处理，从根本上防止竞态与并发写冲突；
  2. **读写分流切分算法（`partition_tool_calls`）**：
     - 将模型单批下发的 `calls: Sequence[ToolCallItem]` 拆解为有序批次：连续的只读工具聚合成 `("parallel", [reads...])`；每一个有副作用的写工具切分为独立的 `("serial", [write])`；
  3. **批内并发执行与独立容错（`execute_tool_calls_batched`）**：
     - `parallel` 批次由 `ThreadPoolExecutor(max_workers=4)` 并发驱动，大幅降低多工具 IO 等待；
     - `serial` 批次按严格因果时序串行调用；
     - **批内故障隔离（Fault Boundary Isolation）**：单个工具抛出异常或底层超时被自动捕获并封装为 `Observation(ok=False, payload={"error": str(e)})`，绝不上浮中断同批其他工具；
     - **保序映射回灌**：返回的 `list[Observation]` 与传入的 `calls` 严格保序一一对应；
  4. **与 Step 4 的无缝协同**：
     - 在同一轮次中，模型同时发起 `archive_current_topic_and_switch`（写操作/上下文瞬移，`WRITE`）与 `read_memory_topic`（只读，`READ`）；
     - `partition_tool_calls` 自动将其切分为 `[("serial", [archive]), ("parallel", [read])]`，**先串行执行话题归档与水印瞬移，随后并发执行新话题记忆读取**，既消除了重复造轮子的冗余，又天然保证了状态机的因果严格性。

   - 早期草案曾构想了独立的 `ParallelRecallCoordinator`，经代码库探查确认已有成熟的 `execute_tool_calls_batched` 与 `partition_tool_calls`，且已被 [`test_react_loop_concurrency.py`](file:///d:/BaiduNetdiskDownload/dailyProjects/Projects/PersonalAgent/personal-agent/services/agent-runtime/tests/test_react_loop_concurrency.py) 充分验证。果断剪除冗余设计，直接以既有模块承接 Step 4 的多工具批调用，保持单一事实来源。
2. **编码器参数化与 Embedding 解耦**：
   - 对话与压缩层（`tokens.py`、`sliding.py`、`storage.py`）统一解耦为环境变量 `os.getenv("TIKTOKEN_ENCODING", "o200k_harmony")`；
   - 知识库与 Embedding 检索层（`knowledge/chunker.py`）保持依赖 `cl100k_base`，防止破坏向量语义。
3. **跨平台 Windows 文本编码铁律**：
   - 所有 Markdown 归档与读取必须显式指定 `encoding="utf-8"`，彻底规避 Windows 下默认 ANSI/GBK 造成的乱码与测试崩溃。
4. **水印非负防御**：
   - 账本初始化或空活跃窗口下 `latest_seq_id` 为 0 时，水印计算强制包裹 `max(0, seq_id - 1)`，杜绝 `-1` 水印穿透导致逻辑倒流。
