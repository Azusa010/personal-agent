## 1. 任务背景与核心业务目标

本项目正从传统的本地 Coding 辅助工具全面演进为具备伴随感、主动性、长期记忆与角色化人格的 **个人全能智能体（Personal Agent）**（融合 Dots / Grok / Claude Code / Codex / Pi 范式）。

在大模型单会话上下文窗口有限、长程推理成本高昂、执行噪音易污染长期心智的现实约束下，本项目建立了完整的 **全生命周期上下文压缩与长程记忆管理体系（7 步演进）**，并由项目主人亲手重构融入了纯 ReAct + 本地账本轨迹管理 + 滑动窗口的 **SOTA 单主循环（DynamicLedgerStrategy）**。

### 核心演进目标全景

1. **确定性审计与大输出防爆**：事件不可变落盘、递增全局 Seq ID、超大工具输出自动脱水落盘为 Blob 指针；
2. **多子代理隔离并发**：Subagent 并发池与独立作用域，成果向上汇聚入主账本，不阻塞主线程；
3. **高水位滑动窗口与真实时钟感知**：双预算（Token / 条数）动态裁剪，时间门卫注入真实墙上物理时钟感知（消灭时间幻觉）；
4. **意图大转向现场封存与三层记忆召回**：180 度大转向时自动归档旧 Epoch 水位线；Tier 1 常驻轻量索引、Tier 2 主题记忆按需加载、Tier 3 原始日志精准检索；
5. **低功耗后台冷记忆提炼**：单调递增独立游标与两阶段启发式 NO_OP 粗筛，纯追加落盘暂存信箱（`inbox.jsonl`）；
6. **无锁竞争 `/dream` 做梦归并引擎**：基于原子重命名锁实现零竞争做梦，增量覆写 7 大正交主题 Markdown，并自动重编轻量常驻 `INDEX.md`；
7. **SOTA 循环与系统提示词认知铁律固化**：纯 ReAct + 本地轨迹管理的单主循环无缝串联本地能力分流，执行器系统提示词明文固化 4 阶段认知作业流程（SOP）。

## 3. 核心设计决策与避坑记录

### 3.1 跨平台 Windows 文件占用与原子替换避坑（Windows File Locking Mechanics）
- **现象**：在 Windows 系统中，若在 `with open(...)` 上下文内执行 `os.replace` 或直接替换正在被其他句柄持有的文件，会直接触发 `[WinError 32] 另一个程序正在使用此文件，进程无法访问`。
- **解决方案**：在 [`AtomicRenameLock`](file:///d:/BaiduNetdiskDownload/dailyProjects/Projects/PersonalAgent/personal-agent/services/agent-runtime/src/personal_agent/conversation/dream/lock.py) 与 [`DreamEngine`](file:///d:/BaiduNetdiskDownload/dailyProjects/Projects/PersonalAgent/personal-agent/services/agent-runtime/src/personal_agent/conversation/dream/engine.py) 中，所有 `.tmp` 临时文件和锁定重命名必须严格脱离 `with` 块、确保句柄完全 `close()` 并显式刷盘（`flush()`）后，再调用 `os.replace`。

### 3.2 暂存信箱改名锁存空窗容错
- **现象**：当 `AtomicRenameLock` 将 `inbox.jsonl` 重命名为 `inbox.lock.jsonl` 进入做梦期间，短时间内 `inbox.jsonl` 在磁盘上暂时不存在。若外部此时调用 `MemoryInbox.count_pending()` 或 `read_pending()`，会引发 `FileNotFoundError`。
- **解决方案**：在 [`MemoryInbox`](file:///d:/BaiduNetdiskDownload/dailyProjects/Projects/PersonalAgent/personal-agent/services/agent-runtime/src/personal_agent/conversation/extractor/inbox.py) 中增加文件存在性守卫，当物理文件未建立或正在改名时，安全返回 `0` 或空列表 `[]`，彻底消除并发偶发异常。

### 3.3 宿主能力（Host RPC）与进程内能力（In-Process Capability）解耦
- **现象**：主循环 ReActLoop 默认会将所有工具调用校验为 `HostExecuteToolParams(capability: CapabilityId)`。然而 `read_memory_topic`、`search_raw_events` 与 `archive_current_topic_and_switch` 属于 Python Runtime 本地进程内能力，不在 Electron 宿主能力枚举（`CapabilityId`）内，会导致 Pydantic 抛出 `ValidationError` 并报 `CAPABILITY_NOT_REGISTERED`。
- **解决方案**：在 [`ReActLoop`](file:///d:/BaiduNetdiskDownload/dailyProjects/Projects/PersonalAgent/personal-agent/services/agent-runtime/src/personal_agent/conversation/loop/react_loop.py) 与 [`DynamicLedgerStrategy`](file:///d:/BaiduNetdiskDownload/dailyProjects/Projects/PersonalAgent/personal-agent/services/agent-runtime/src/personal_agent/conversation/loop/strategy.py) 中引入可选的 `local_executor` 拦截器。在组装 RPC 参数前优先交由 `local_executor` 处理，本地直接产生 `Observation` 返回，既不污染跨端 RPC 契约，又赋予了本地单主循环调度三层记忆与现场封存的完整自由。

### 3.4 认知提示词 SOP 显式化（Prompt Solidification）
- 在 [`executor.py`](file:///d:/BaiduNetdiskDownload/dailyProjects/Projects/PersonalAgent/personal-agent/services/agent-runtime/src/personal_agent/conversation/instructions/executor.py) 中，将长程记忆的认知逻辑深度编织进 4 阶段 SOP 中：
  - **阶段 1（现状审视）** 明确意图转向探测与 Tier 1~3 索引核查；
  - **阶段 3（决策分支）** 明确 180 度大转向必须优先调度 `archive_current_topic_and_switch` 封存旧现场并重置水位线；领域与偏好知识需根据 `<memory_index>` 调用 `read_memory_topic` 定向加载；
  - 严格保持与不可违反安全规则、代码推理优先原则以及遇错自适应热修闭环的绝对兼容。
