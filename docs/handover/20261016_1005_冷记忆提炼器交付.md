## 1. 任务背景与核心业务目标

本项目正从传统的本地 Coding 辅助工具演进为具备伴随感、主动性、长期记忆与角色化人格的 **个人全能智能体（Personal Agent）**。

在长周期、多轮次人机交互中，主事件账本（`main_session_events.jsonl`）以不可变、只追加的方式记录了全量交互历史（冷数据）。若直接将未经加工的原始事件抛给知识库或记忆合并模块，会导致大量临时调试报错、中间探测（如 `ls`、`pwd`）、心跳探针和寒暄问候倒灌污染长期记忆，并浪费昂贵的大模型 Token。

为此，**Step 5：带 NO_OP 过滤的后台冷记忆提炼器（Cold Memory Extractor）** 建立了专门的冷数据异步提炼流水线：
1. **独立提取游标（`ExtractorCursor`）**：以非阻塞方式异步扫描主账本，持久化已处理的 `last_extracted_seq_id`，保证重启不丢进度、不重复提炼、严格单调防倒流；
2. **两阶段噪音过滤与 `NO_OP` 机制**：
   - **前置粗筛**：通过启发式规则判定，若整批事件全为心跳、报错堆栈或日常寒暄，直接短路为 `NO_OP`，不调用大模型，直接推进游标，节约 80% 无效 Token 开销；
   - **精炼质检**：针对有效 `user` 轮次调用提炼函数，过滤掉 `action == "NO_OP"` 或置信度低于阈值（`< 0.7`）的条目；
3. **暂存信箱纯追加（`MemoryInbox`）**：提炼出的原子偏好、架构约定与业务事实以只追加（Append-Only）方式落盘至 `./memory/inbox.jsonl`，为 Step 6（基于文件锁的 `/dream` 归并引擎）准备原料。

### 2.1 模块职责与契约明细

#### 1. 数据模型契约 (`models.py`)
- **`MemoryCategory`**：7 大高内聚正交分类：
  - `user_profile`（主人画像与生活/沟通习惯）
  - `persona_dynamics`（智能体角色设定与交互契约/共处默契）
  - `active_goals`（长期目标、当前关注点与攻坚愿景）
  - `coding_standards`（工程规范、代码风格、测试框架与工具链约束）
  - `project_context`（系统架构、模块设计、业务背景与物理环境）
  - `key_decision`（重大历史决议、设计选型定论与避坑记录）
  - `other`（开放兜底扩展）
- **`CandidateMemoryItem`**：单条候选事实模型，包含 `id`, `action`, `category`, `content`, `confidence`, `source_seq_range`, `extracted_at`, `status`；
- **`ExtractionResult`**：批次提炼汇总模型，包含 `items`, `processed_events_count`, `from_seq_id`, `to_seq_id`, `noop_count`。

#### 2. 提取游标管理 (`cursor.py`)
- **`ExtractorCursor`**：
  - 属性 `last_extracted_seq_id` 记录消费进度；
  - 构造时自动从 `cursor_file`（如 `extractor_cursor.json`）倒序解析加载历史断点；
  - `advance(new_seq_id)` 保证严格单调防倒流（`max` 保护），并实时向磁盘刷入最新状态与时间戳。

#### 3. 暂存信箱读写 (`inbox.py`)
- **`MemoryInbox`**：
  - 管理 `./memory/inbox.jsonl`，持有内部 `threading.Lock` 保证并发追加安全；
  - 初始化时自动检查并创建多级父目录；
  - `append` / `append_batch` 使用 UTF-8 编码、换行符 `\n` 只追加写入；
  - `read_pending() -> list[CandidateMemoryItem]` 批量读取待归并候选条目；
  - `count_pending() -> int` 返回待处理条目数量。

#### 4. 强噪音过滤 (`filter.py`)
- **`is_noise_event(event: LedgerEvent) -> bool`**：
  - 瞬态事件（`event.ephemeral == True`）判定为噪音；
  - 中间过程细节（`tool_call`, `tool_result`, `system`, `subagent`）直接剔除；
  - 用户输入中的日常短回复与寒暄问候（如“好的”、“1”、“你好啊”、“hi”）判定为噪音；
  - 包含实质内容的文本判定为非噪音。

#### 5. 核心调度提炼器 (`extractor.py`)
- **`ColdMemoryExtractor`**：
  - 依赖注入主账本 `ledger`、信箱 `inbox`、游标 `cursor` 与可插拔提炼函数 `extract_fn`；
  - 内部线程锁包裹完整的批处理区间，防止多线程并发调用时重复提取相同批次；
  - `extract_next_batch()` 执行“粗筛短路 $\rightarrow$ 提取函数调用 $\rightarrow$ 置信度/NO_OP 过滤 $\rightarrow$ 信箱写入 $\rightarrow$ 游标推进”流水线；
  - `drain_all(max_batches=50)` 循环消化积压事件，直到账本对齐。

## 3. 核心设计决策与避坑记录

1. **解耦 `sidecar.llm_client`，采用依赖注入 `extract_fn`**：
   - 早期探讨曾考虑复用 `sidecar` 模块，但深入分析发现现有 `sidecar` 是挂载在 ReAct 主循环关键路径上的**热路径安全守卫**（阻塞式、瞬态）；
   - 冷记忆提炼是**冷路径异步/后台任务**，必须解耦。通过将 `extract_fn` 作为可插拔参数传入，既保持了提炼器的高内聚与可测试性，又彻底规避了热路径延迟与循环依赖。
2. **精简合并 7 大正交分类，消除“分类摇摆”**：
   - 将散碎的技术栈、代码规范整合为 `coding_standards`，将架构、领域规则与环境事实整合为 `project_context`；
   - 既兼顾了 Dots / Pi / Grok 范式的个人伴随心智，又保留了 Claude Code 的硬核工程约束，且完美一对一映射到 Step 6 的 7 大落盘 Markdown 账本。
3. **聚焦 `user` 轮次，剔除工具调用噪音**：
   - 确立了以主人的直接 Prompt 为唯一事实源泉的原则，将 `tool_call` 和 `tool_result` 判定为中间执行态噪音，避免过程中的命令回显污染长期事实。
4. **`reverse_read` 尾部空行解码避坑**：
   - 底层 `reverse_read` 倒序切分文件时，尾部 `\n` 会产生首个空字符串 `""`，直接 `json.loads` 会抛出 `JSONDecodeError`；
   - 在 `cursor.py` 反序列化循环头部增加 `line.strip()` 空行过滤，彻底消除隐患。
5. **两阶段架构心智解耦**：
   - 明确了 `filter`（`is_noise_event`）仅作用于输入端原始事件 `LedgerEvent` 用于短路省 Token；
   - 输出端候选条目 `CandidateMemoryItem` 则完全基于原生字段（`action != "NO_OP"` 和 `confidence >= min_confidence`）做质检过滤，两者职责边界完全清晰。
