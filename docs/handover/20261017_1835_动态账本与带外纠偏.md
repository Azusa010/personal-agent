## 1. 任务背景与核心业务目标

本项目正从传统的本地 Coding 辅助工具全面演进为具备伴随感、主动性、长期记忆与角色化人格的 **个人全能智能体（Personal Agent）**（融合 Dots / Grok / Claude Code / Codex / Pi 范式）。

在原有架构中，Agent 依赖“外部独立规划器生成静态步骤 -> 外部逐步驱动 ReAct -> 遇错重走外部重规划”的传统硬切范式。该范式存在**计划僵化、步骤间缺乏即时动态账本勾选与追加排错步骤、工具超大输出容易撑爆上下文窗口、模型在步数将尽时缺乏带外纠偏与收敛指引**等核心痛点。

针对上述瓶颈，本次演进全面对标 Claude Code / Codex / SWE-agent 的 SOTA 循环机制，推进并完成了前两个核心阶段：
1. **Phase 1（P1 动态任务账本 / In-Loop Dynamic Task Ledger）**：将任务清单（Todo/Task）作为一等公民工具暴露给模型，支持循环内自主读写、推进并严格保持单一 `in_progress` 约束，动态反哺下一次决策。
2. **Phase 2（P2 长程上下文工程与带外纠偏 / Context Engineering & `<system-reminder>` Steering）**：扩充大工具输出自动截断白名单，定义带外 `<system-reminder>` 契约并末尾注入（确保 KV Cache 前缀命中），并在 ReActLoop 单主循环内基于 70% 预警与 85% 紧迫预算消耗动态注入转向提醒，促成优雅收敛。

## 3. 核心设计决策与避坑记录

### 3.1 轨迹文件边界与单循环执行边界的严格分离（铁律澄清）
- **现象与排查**：在设计长程上下文工程时，曾一度混淆了 `SlidingWindowLedger.find_safe_compaction_boundary` 的职责。
- **核心认知澄清**：`find_safe_compaction_boundary` 属于 **持久化主事件账本（`MainEventLedger`）**，其职责是跨多轮会话逆向对齐用户轮次（User-Turn Boundary），维护成对工具交互保护（绝不切断 `tool_call` 与 `tool_result`）。它**绝不能**随意侵入单轮 ReActLoop 的内部执行步。单轮内部的防爆与长程控制由 **工具输出截断（`truncate_strings`）** 与 **带外系统提醒（`<system-reminder>`）** 协同保障。

### 3.2 KV Cache 友好的带外系统提醒（`<system-reminder>` Tail Injection）
- **现象**：如果将系统预算预警直接修改在开头的 `system` 消息中，会导致每一轮模型调用的系统提示词均发生变动，直接击穿云端大模型的 KV Cache 前缀缓存，导致延迟与费用飙升。
- **解决方案**：对齐 Claude Code 官方实践，将 `systemReminders` 作为独立的 `role="user"` 消息包裹在 `<system-reminder>\n...\n</system-reminder>` 标签中，紧随观察结果追加在消息流末尾。这保证了历史轮次与工具前缀 100% 稳定命中 KV Cache，同时给予模型最高优先级的即时转向引导。

### 3.3 大输出安全截断白名单与标识符保护
- **设计决策**：`TRUNCATABLE_KEYS` 严格采用白名单机制。将长内容字段（`content`, `stdout`, `stderr`, `output`, `summary`, `snippet`, `answer`）纳入截断范围（默认保留上限 2000 字符 + `…[truncated]`），但坚决不对 `path`, `code`, `exitCode`, `name` 等结构化标识符执行截断，彻底避免路径被啃坏导致的静默执行失败。

### 3.4 步数预算与单 Step 吞吐的工程反思
- **深层痛点**：目前全局默认的 12~15 步预算属于早期玩具级 Agent（2023 年防死循环熔断）遗留设计。在真实 Coding 任务中，子 Agent 刚完成几处文件检索便触碰 70% 报警并草草交差，严重制约了复杂工程探索能力。
- **SOTA 演进共识**：后续必须放宽基础步数池（参考 SWE-agent 的 30~50 步或 Claude Code 的费用预算制），并引入**并发工具调用（Parallel Tool Calls）**——单轮一次性下发多个 `file_read`，把多次工具消耗压缩进单一 Step。
